# Задание 1. Исследование моделей и инфраструктуры

Бот нужен сотрудникам QuantumForge: он ищет ответ во внутренней базе (регламенты, архитектура, инструкции). Часть документов конфиденциальна, поэтому тексты остаются в компании. Стек берём простой: одна модель, одна библиотека поиска, один сервер.

## 1. LLM

| Критерий | Локальная модель (Hugging Face) | Облако (OpenAI / YandexGPT) |
| --- | --- | --- |
| Качество ответов | Достаточное, если отвечать по найденному фрагменту | Обычно выше на общих вопросах |
| Скорость | Без видеокарты отвечает медленно | Ответ приходит быстро по API |
| Стоимость | Платим за свой сервер, запросы бесплатные | Платим за каждый запрос |
| Развёртывание | Скачать модель и запустить у себя | Достаточно ключа API |

Беру локальную модель: куски внутренних документов не отправляются провайдеру.

## 2. Эмбеддинги

Эмбеддинг — числовой отпечаток текста. По нему ищут похожие куски документов.

| Критерий | Sentence-Transformers | OpenAI Embeddings |
| --- | --- | --- |
| Скорость индекса | Считается на своём сервере, для учебной базы это минуты | Быстро, но каждый текст уходит в API |
| Качество поиска | Хватает, чтобы найти нужный фрагмент | Чуть точнее на общих текстах |
| Стоимость | Бесплатно | Платно, растёт вместе с объёмом документов |

Беру локальную модель `all-MiniLM-L6-v2`: индекс строится у себя, тексты остаются в компании.

## 3. FAISS и ChromaDB

| Критерий | FAISS | ChromaDB |
| --- | --- | --- |
| Скорость поиска и индекса | Быстрый поиск, индекс хранится файлом | Медленнее на простом поиске, зато умеет фильтры |
| Внедрение и поддержка | Библиотека внутри бота, отдельный сервис не нужен | Отдельная база: её надо запускать и следить |
| Удобство | Ищет ближайшие фрагменты, подписи к ним храним сами | Удобнее хранить текст, путь к файлу и фильтры |
| Стоимость | Бесплатно | Бесплатно, но нужно ещё одно приложение и память под него |

## 4. Сервер

Для локальной небольшой LLM, эмбеддингов и FAISS:

- CPU: 8 ядер
- RAM: 32 ГБ
- GPU: 1 видеокарта на 16 ГБ, чтобы ответы не ждали подолгу
- Диск: 100 ГБ SSD под модель и индекс

Без видеокарты бот тоже запускается, ответы просто дольше.

## Варианты

| Вариант | Состав | Плюс | Минус |
| --- | --- | --- | --- |
| 1. Всё в облаке | OpenAI, OpenAI Embeddings, ChromaDB | Быстро запустить | Документы уходят наружу, плата за запросы |
| 2. Гибрид | YandexGPT, локальные эмбеддинги, FAISS | Индекс свой | В запрос к модели всё равно попадает текст из базы |
| 3. Всё локально, FAISS | Hugging Face, Sentence-Transformers, FAISS | Данные внутри, мало частей | Нужен свой сервер с видеокартой |
| 4. Всё локально, ChromaDB | Hugging Face, Sentence-Transformers, ChromaDB | Данные внутри, удобные фильтры | Ещё один сервис, который надо сопровождать |

Выбираю вариант 3.

**Векторная база — FAISS.** Это библиотека внутри бота: индекс лежит в файле, отдельный сервер не ставим. Для поиска по внутренней базе этого хватает, сопровождать проще, плата за хранилище не нужна.

# Задание 2. Подготовка базы знаний

Взял вселенную Star Wars: вводные тексты со [starwars.fandom.com](https://starwars.fandom.com), 42 страницы. В каждой странице одна сущность — персонаж, планета, техника или событие.

Скрипт `prepare_knowledge_base.py` убирает разметку и подставляет вымышленные названия из `terms_map.json`. Меняются не только имена, но и планеты, расы и техника. Например, Darth Vader становится Xarn Velgor, Death Star — Void Core, the Force — Synth Flux. Фразы остаются понятными, а по старым названиям мир уже не узнать.

Результат: папка `knowledge_base/` (42 файла `.md`) и словарь `terms_map.json`.

# Задание 3. Создание векторного индекса базы знаний

Эмбеддинги считает локальная модель [all-MiniLM-L6-v2](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2). У каждого фрагмента вектор из 384 чисел.

Скрипт `build_index.py` берёт 42 файла из `knowledge_base/` и режет их через `RecursiveCharacterTextSplitter` на куски примерно по 170 слов. У чанка сохраняются путь к файлу, заголовок и позиция в тексте. Векторы складываются в FAISS: индекс — `faiss.index`, тексты чанков — `chunks.json`. В индексе 147 чанков, сборка заняла около 3 секунд.

Проверка поиска, по два ближайших фрагмента:

- «Who is Lir Kass?» — `lir-kass.md`: Lir Kass, легендарный Senior Seeker времён Iron Dominion.
- «What is the Void Core?» — `void-core.md`: Void Core, мобильная боевая станция.
- «What is Edict 66?» — `edict-66.md`: секретный приказ, по которому Seeker объявлены предателями.
